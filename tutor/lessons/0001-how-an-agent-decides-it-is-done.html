How an agent decides it is done

The big idea: three things can end a loop 2 min

An agent loop is a cycle: the model looks at the conversation, either asks for a tool (read a file, run tests) or answers, your code runs the tool, the result goes back, repeat (Claude docs, How tool use works).

"Done" is decided in three layers:

  • The model decides it has nothing left to do and answers without calling a tool. This is the normal ending.
  • Limits set by you (turns, budget, output tokens) cut it off, done or not.
  • Checks you write look at the result and can send the agent back to work.

Layer 1: the model stops asking for tools 2 min

Every response from the Claude API carries a stop_reason, a field saying why the model stopped generating. The canonical loop is just this (Build a tool-using agent):

while response.stop_reason == "tool_use":
    result = run_tool(...)            # your code does the work
    messages.append(result)           # feed the result back
    response = client.messages.create(..., messages=messages)

# loop is over: end_turn, max_tokens, stop_sequence, refusal...
  • tool_use: "Claude is calling a tool that you need to run." Keep looping.
  • end_turn: Claude "completed its response naturally." This is the model saying "I'm done" (Handling stop reasons).

The Agent SDK, which runs Claude Code's own loop, says the same: turns continue "until Claude produces output with no tool calls" (How the agent loop works).

A common mix-up (M1)

"The agent stopped, so the task is finished." Tempting, because the final message usually says it is finished. But end_turn only means the model believes it is done. An agent that writes "all tests pass" without running them ends with the same end_turn as one that ran them. That is why Anthropic stresses getting "ground truth" from the environment at each step (Building effective agents).

Check yourself

A response arrives with stop_reason: "tool_use" and a request to run pytest. What does the loop do next?

Show the answer

It runs pytest and sends the output back as a tool result. tool_use is the one stop reason that keeps the loop going.

Layer 2: limits stop it from outside 2 min

Anthropic's guidance: tasks often end on completion, but it is "common to include stopping conditions (such as a maximum number of iterations) to maintain control" (Building effective agents). A limit ending the loop is not the task being done.

Analogy, one mapping: the game clock is max_turns; when it runs out the game ends no matter who was mid-play, and the box score says "time expired", not "won".

max_tokensOutput hit your token limit. The answer is cut off: raise the limit or continue.
pause_turnServer tools (like web search) hit their iteration cap. "The work isn't complete": send it back to continue.
error_max_turnsAgent SDK ran out of turns. No result text at all.
error_max_budget_usdAgent SDK hit your spend cap. Also no result.

Sources: Handling stop reasons; How the agent loop works.

One counting detail: in the SDK, max_turns counts each tool-calling turn plus one for the final text-only answer. Forget the plus one and the run ends with error_max_turns and no answer.

A common mix-up (M2)

"Anything other than tool_use means success." The loop does exit on any other stop reason, but the docs say these can mean "stopped for another reason that your application should handle." A max_tokens ending is a truncated answer, not a finished one.

Layer 3: a check can refuse the stop 1 min

Because the model's "done" is only a belief, you can add a check that runs when it tries to stop. In Claude Code, a Stop hook is a script that fires "when Claude finishes responding"; if it returns "decision": "block" with a reason, Claude does not stop and gets the reason as its next instruction (Hooks reference):

{ "decision": "block",
  "reason": "Tests are still failing. Fix them before finishing." }

This turns "the model thinks it's done" into "the model thinks it's done and the check agrees."

Check yourself

An SDK run returns a ResultMessage with subtype error_max_budget_usd. What do you know?

Show the answer

A spend limit ended the run. The task may or may not be done, and there is no result text to read.

Summary 1 min

  • The loop runs while the model asks for tools; a reply with no tool call is the model's "done".
  • The model's "done" is a belief. Verify with ground truth: tests, files, outputs.
  • Limits (max_tokens, pause_turn, max turns, max budget) end the loop without meaning success.
  • A Stop hook can block a premature stop and send the agent back with a reason.
