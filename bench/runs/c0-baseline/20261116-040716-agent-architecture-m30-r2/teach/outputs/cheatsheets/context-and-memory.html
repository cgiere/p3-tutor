Context and memory in an agent

From lesson 0001. Source: Anthropic, Effective context engineering for AI agents.

Core rule

The model has no memory. It reads only the context window on each call. Anything remembered is stored outside the model and put back by your program.

Terms

TermMeaning
Context windowThe tokens the model reads for one call: instructions, tool descriptions, conversation, tool results, retrieved text. Limited in size.
Context rotRecall of information in the window gets worse as the window fills.
SessionOne conversation or request. The window is discarded at its end.
CompactionSummarize a long context and start a fresh window with the summary.
Retrieval (RAG)Search a stored collection and put only the best chunks in context.
NotesFacts the agent saves outside the window and reads back later.

Where does it go?

InformationPut it inWhy
Short rules that apply to every requestContext, every callCheap and always needed
Long manualsStore; retrieve chunksToo big and mostly irrelevant per question
Per-student facts (training, preferences)Notes or a database lookupMust outlive the session
Tool results during a requestContext (appended by the program)The model needs them for the next step

Cost rule of thumb

Input tokens for a request = the sum, over every model call, of everything in the context at that call. A result added at call k is paid for again on every later call.
